## 1. PROBLEMA: Módulos No Funciona - Error de Conexión CORS

**Error en el navegador:**
```
No se pudo cargar usuarios: No hay conexion con el backend (https://192.168.1.129:5001). 
Asegura que el backend este iniciado y que CORS permita https://192.168.1.129:8443.
```

### Causa Raíz
- Los backends (salto y fútbol) estaban limitando CORS solo a `localhost`
- El frontend en LAN (`https://192.168.1.129:8443`) era rechazado
- Las restricciones CORS en `run_all.bat` no permitían acceso desde el origen real

### Solución Aplicada

**Archivo:** `scripts/run_all.bat`

```batch
# ANTES (restringido a localhost)
set CORS_ORIGINS=https://localhost:8443,https://127.0.0.1:8443,http://localhost:8080,http://127.0.0.1:8080

# DESPUÉS (abierto para desarrollo LAN)
set CORS_ORIGINS=*
```

**Cambios en 3 servicios:**
- Backend Salto (puerto 5001)
- Backend Fútbol (puerto 5002)
- Backend Sensor (puerto 5000)

**Impacto:** Ambos módulos ahora pueden cargar usuarios y datos desde el frontend en LAN.

## 3. PROBLEMA: Corrupción de ID de Usuario en Fútbol

**Error observado:**
- `id_usuario` se mostraba como `[object Object]` o `NaN` en uploads
- Los vídeos se rejazaban con "id_usuario debe ser un entero"

### Causa Raíz
- `getUsuarioActivo()` en `futbol.js` retornaba números inválidos
- El helper `window.UsuarioActivo` no existía o devolvía objetos
- `analizarGolpeo()` en `api_futbol.js` no validaba el ID antes de enviarlo

### Solución Aplicada

**Archivo:** `integration/web/js/futbol.js`

Endurecimiento de `getUsuarioActivo()`:

```javascript
function getUsuarioActivo() {
    // Intenta usar helper global si existe
    if (typeof window !== 'undefined' && window.UsuarioActivo) {
        const u = window.UsuarioActivo.obtener();
        const idUsuario = Number(u && u.idUsuario);
        return Number.isFinite(idUsuario) && idUsuario > 0 ? { idUsuario } : null;
    }
    
    // Fallback a sessionStorage
    const rawIdUsuario = sessionStorage.getItem('idUser');
    if (!rawIdUsuario) {
        return null;
    }
    
    // Intenta parsear si viene como JSON
    let idUsuario = Number(rawIdUsuario);
    if (!Number.isFinite(idUsuario)) {
        try {
            const parsed = JSON.parse(rawIdUsuario);
            if (parsed) {
                idUsuario = Number(parsed.id_usuario || parsed.idUser || parsed.id || parsed);
            }
        } catch (_e) {
            return null;
        }
    }
    
    // Valida que sea número positivo
    if (!Number.isFinite(idUsuario) || idUsuario <= 0) {
        return null;
    }
    
    return { idUsuario };
}
```

**Archivo:** `integration/web/js/api_futbol.js`

Validación en `analizarGolpeo()`:

```javascript
async function analizarGolpeo(videoBlob, opciones = {}) {
    const formData = new FormData();
    formData.append('video', videoBlob, 'golpeo.webm');
    
    // ANTES: simplemente verificaba existencia
    // if (opciones.idUsuario) {
    //     formData.append('id_usuario', String(opciones.idUsuario));
    // }
    
    // DESPUÉS: validación estricta
    const idUsuarioNum = Number(opciones.idUsuario);
    if (Number.isFinite(idUsuarioNum) && idUsuarioNum > 0) {
        formData.append('id_usuario', String(idUsuarioNum));
    }
    
    // ... resto del código
}
```

**Impacto:** Los uploads de vídeos de fútbol ahora nunca envían IDs inválidos.
